# PRD: 라커룸

## 개요
플랩풋볼처럼 풋살 소셜 매치 플랫폼을 만든다. 열린 매치에 개인이 한 자리씩 참가하고, 최소 인원이 모이면 매치가 확정된다. 팀이 없거나 인원이 모자라도 혼자 공을 찰 수 있다.

## 목적
- 실제 서비스(플랩풋볼)의 구조를 분석하고, 그 핵심 문제를 직접 구현하고 측정하며 해결한다.
- 실운영은 하지 않는다. 시연은 샘플 데이터로 한다.

## 사용자와 문제
| 사용자 | 겪는 문제 |
|---|---|
| 개인 플레이어 | 팀이 없거나 인원이 모자라 혼자서는 공을 차기 어렵다. 직접 사람을 모으고 구장을 잡는 일이 번거롭다. 인기 시간대 매치는 금방 마감된다 |
| 서비스 관리자 | 구장과 매치를 등록하고, 인원이 모이지 않은 매치를 정리해야 한다 |

## 사용자 스토리 (MVP)
- 플레이어로서, 날짜별로 열린 매치를 보고 지역, 시간, 형식, 성별로 걸러 보고 싶다
- 플레이어로서, 원하는 매치에 한 자리를 신청하고 내 매치 내역에서 확인하고 싶다
- 플레이어로서, 기한 안에 참가를 취소하고 싶다
- 플레이어로서, 마감된 매치에 대기를 걸고 자리가 나면 알림을 받고 싶다
- 플레이어로서, 내가 참가한 매치가 확정되거나 인원 미달로 취소되면 알림을 받고 싶다

## MVP 범위

### 이용자
- 카카오 로그인, 첫 진입 시 추가 정보 입력(성별)
- 내 정보: 이름 수정 (성별은 수정 불가)
- 매치 목록: 날짜 탭, 매치 카드(시간, 구장과 코트, 매치 형식, 성별, 남은 자리, 상태)
- 매치 필터: 지역, 시간대, 매치 형식, 성별, 마감 가리기
- 매치 상세: 구장 정보, 참가 인원과 정원, 참가비 표시, 규칙과 취소 안내
- 참가 신청, 참가 취소, 내 매치 내역
- 마감된 매치에 대기 등록
- 알림: 빈자리 발생, 매치 확정, 매치 자동 취소 (웹 푸시 + 알림함)
- PWA (홈 화면에 추가)

### 서비스 관리자
- 구장, 코트 데이터는 시드 스크립트로 넣는다
- 매치 생성 API (화면 없이 관리자 권한으로만 호출)

### 시스템
- 매치 시작 3시간 전 최소 인원 미달이면 자동 취소, 충족이면 확정하고 참가자에게 알림
- 매일 고정 시각에 새 날짜의 매치를 공개

## 핵심 정책
| 항목 | 결정 |
|---|---|
| 참가 단위 | 1인 1자리 |
| 정원 | 매치마다 최소 인원, 최대 인원 |
| 매치 공개 범위 | 오늘부터 14일 뒤까지 조회, 신청 가능 (설정값). 매일 고정 시각에 새 날짜가 열림 |
| 매치 상태 | 모집 상태: 모집중 → 마감(최대 인원 참), 취소가 나면 다시 모집중. 진행 상태: 미정 → 확정(최소 인원 충족) 또는 취소(미달) → 종료. 확정된 매치도 남은 자리가 있으면 시작 전까지 신청 가능 |
| 참가 취소 | 매치 시작 24시간 전까지 (설정값) |
| 자동 확정, 취소 | 매치 시작 3시간 전에 판단 (설정값) |
| 대기와 빈자리 알림 | 마감된 매치에 대기 등록. 참가 취소로 자리가 나면 대기자 전원에게 동시 알림, 먼저 신청한 사람이 가져감 |
| 중복 참가 방지 | 같은 매치 두 번 참가 불가, 시간이 겹치는 매치 동시 참가 불가 |
| 정원 초과 방지 | 동시에 신청이 몰려도 최대 인원을 넘지 않음 |
| 성별 조건 | 매치마다 남녀 모두/남자/여자. 이용자 성별은 가입 후 직접 선택, 이용자는 수정 불가(잘못 고른 경우 관리자가 수정). 조건과 다르면 신청 불가 |
| 이름 | 카카오 닉네임(원본)과 서비스 이름을 따로 저장. 첫 로그인 때 원본을 저장하고 서비스 이름 초기값으로 복사. 이용자는 서비스 이름만 수정, 로그인 때 덮어쓰지 않음 |
| 계정과 권한 | 이용자 / 서비스 관리자. 카카오 로그인. 회원과 로그인 수단을 분리해 설계 |
| 알림 | 웹 푸시(FCM) + 앱 내 알림함. 이벤트와 발송을 분리해 알림 종류를 쉽게 추가 |

## 하지 않을 것 (MVP)
참가비 결제, 구장 예약(대관), 관리자 화면, 레벨과 매너 평가, 매니저, 팀, 리그, 게스트, 친구와 함께 신청, 구장 커뮤니티, LLM 기능, 순번 알림, 매치 전날 안내와 리뷰 요청 알림, 이메일과 알림톡

## 이후 단계
- 1.5단계: 참가비 결제(토스페이먼츠 테스트), 모니터링과 단계별 기술 도입
- 2단계: 구장 예약. 구장의 코트 시간을 매치와 대관이 함께 쓰는 구조 (MVP 설계 때 염두에 둔다)
- 추후: 관리자 화면, 레벨과 매너 평가, 팀과 리그, 알림 확장, 구장 커뮤니티

## 성공 지표
실운영을 하지 않으므로 완성 기준과 기술 목표로 정한다.
- 참가 → 취소 → 빈자리 알림 → 다른 사람 재참가 흐름 E2E 통과
- 정원 1자리에 동시 신청이 몰려도 정원을 넘지 않는 테스트 통과
- 정해진 시점에 매치가 자동 확정 또는 취소되고 참가자에게 알림
- HTTPS 배포 후 휴대폰에서 PWA 설치와 알림 수신
- 기술 목표: 새 날짜 오픈 시각의 인기 매치 동시 신청 상황에서 p95 응답 시간 OO ms 이하, 정원 초과 0건 (숫자는 첫 부하 테스트 기준선을 보고 정함)

## 가정 (부하 테스트 시나리오의 전제)
- 매일 새 날짜가 열리는 시각에 인기 매치(주말 저녁 등)로 정원보다 훨씬 많은 사람이 동시에 신청한다
- 빈자리 알림을 받은 대기자들이 한꺼번에 신청한다
- 매치 하나의 정원은 10~18명 수준이다
- 조회(매치 목록)가 신청보다 훨씬 많다
- 수치는 측정 전에 가정으로 명시하고, 측정 결과로 다시 조정한다

## 설계 중 정할 것
- 구장, 코트 정보 항목
- 매치 형식별 정원 기본값
- 지역 필터 기준
- 매치 시작, 취소 시 대기 목록 정리 방식
- 새 날짜가 열리는 정확한 시각

## 참고: 플랩풋볼 구조 (2026-10-29 확인)
- 매치 목록: 날짜 탭(약 2주), 시간, 구장과 코트, 형식(5vs5, 6vs6), 상태(마감임박, 확정임박), 남은 자리
- 필터: 지역, 상태, 시간(18시, 20시, 22시 이후), 형식, 성별, 레벨, 시설, 마감 가리기
- 알림 흐름: 매치 확정 → 전날 일정 안내 → 매치 후 리뷰 요청
